# MoMedA_EnData

Мультиагентная медицинская система на локальных моделях: маршрутизатор
выбирает специалиста, 14 агентов выдают предварительные диагнозы,
мастер-агент формулирует итоговый. Все модели — файнтюны Qwen2.5-3B.
Обучение и инференс — одна RTX 3090 (24 ГБ). Внешних сервисов нет.

## Архитектура

```
RU случай → [MiLMMT-46-1B: RU→EN, резидентно] → роутер med-router-en-v2-3b
  (14 классов, резидентно) → агент med-spec-<slug>-3b (LRU=1):
  ### Рассуждение + ### Предварительный диагноз (EN) → мастер med-chief-3b
  (резидентно): ### Рассуждение + ### Итоговый диагноз (EN)
  → [base Qwen2.5-3B: EN→RU, транзиентно] → RU-ответ
```

VRAM: резидентно роутер 6.2 + мастер 6.2 + MiLMMT 2.0 ГБ; агент 6.2 (LRU);
Qwen-переводчик 6.2 (только шаг выхода, агент к этому моменту выгружен).
Пик 19.8 из 23.5 ГБ. Переводчик и агент никогда не находятся в памяти
одновременно: их сумма с роутером и мастером превышает объём карты.

## Шаг 1. Источники данных

| Источник | Лицензия | Использование |
|---|---|---|
| MedMCQA, 193k вопросов (88% с объяснениями) | Apache-2.0 | виньетки агентов, роутер, данные мастера |
| MTSamples, 4 999 клинических заметок, ~40 специальностей | CC0 | роутер |
| MedQuAD, 47 441 QA с сайтов NIH | CC-style | Онколог (CancerGov 729), Невролог (NINDS 1 087) |
| MedQA-USMLE, 11 451 виньетка | CC-BY 4.0 | внешний eval, данные мастера |
| HealthCareMagic-100k, 112k консультаций | нет явной — только исследование | псевдо-разметка 7 специальностей |
| DDXPlus, 1.3M синтетических пациентов, дифдиагнозы | CC-BY | жалобы для роутера, данные мастера, e2e |

Проверка первоисточников вскрыла: крупнейшие папки MedQuAD (ADAM 17k,
Drugs 13k) распространяются без ответов из-за копирайта MedlinePlus и для
обучения бесполезны; объём онкологического подмножества — 729 QA, а не
«~13k», как указано в обзорах.

## Шаг 2. Разметка по 14 специалистам

Соответствия «метка источника → специалист» — `scripts/specialties.py`
(единый источник таблиц). Схема:

- 9 классов напрямую из предметов MedMCQA (Medicine, Surgery, Gyn&Obs,
  Pediatrics, Skin, Ophthalmology, ENT, Dental, Orthopaedics);
- 5 классов из тем MedMCQA (Neurology, Gastrointestinal, Nephrology/Urology
  и др.) — вопросы изымаются из предметных пулов, чтобы не дублировались;
- базовые предметы (Anatomy, Pharmacology, …) не размечаются — ~99k в резерв;
- консультации HCM размечаются словарными правилами (счёт ≥ 3) для 7
  специальных классов.

Валидация псевдо-разметки: обученный на этих данных роутер на тесте
распознаёт HCM-тексты с точностью 93% — разметка принята. Утилита очистки:
HTML-теги, дедупликация MD5 по вопросу, фильтры длины, seed 42 — полная
воспроизводимость перегенерации.

Унификация формата (`--uniform-format`): консультационные ответы получают
блок «### Предварительный диагноз», извлекаемый регуляркой из
диагностических формулировок самого врача («suggests», «consistent with»,
«due to», …). Покрытие 44% консультаций; остальные не содержат диагноза
(чисто реферальные) и фабрикация для них не допускается.

## Шаг 3. Маршрутизатор

Датасет 17.6k: вопросы MedMCQA, заметки MTSamples, жалобы из улик DDXPlus
(декодируются в текст через `release_evidences.json`), HCM-консультации;
балансировка по классам, целевой формат «Рекомендуемый специалист: <Класс>.».

- **v1**: 72.7% на смешанном тесте; по источникам — ddxplus 97%, hcm 93%,
  mtsamples 73%, medmcqa 66%.
- **v2**: расширен DDX-маппинг (7 классов вместо 2; правила сверены со всеми
  49 патологиями), датасет перегенерирован, переобучение — **76.6%**,
  DDX-жалобы 96%. Причина v2 — провал e2e v1 (шаг 8): роутер v1 был обучен
  до расширения маппинга и относил онко-/гастро-/невро-жалобы к Терапевту.

## Шаг 4. Агенты-специалисты

14 полных файнтюнов на максимальном доступном объёме (суммарно 113.7k
примеров; 13/14 классов по 4–16k, Проктолог 1.1k). Рецепт: unsloth + HF
Trainer, bf16, ChatML, маска лосса вне ответа ассистента, batch 1×accum 16,
1 эпоха. Время обучения 6–70 минут на агента.

Метрики (единый пересчёт по сохранённым ответам, `runs/FINAL_METRICS.md`):
MCQ на своих виньетках 50–85%, USMLE 44–79%, чистота EN ~100%. Выявлены два
профиля: «экзаменационные» агенты (MedMCQA ≥ 80%) держат формат в 81–99%;
«консультационные» (HCM-доминирующие) на виньетках переключаются в
экзаменационный режим (64–100% формата на USMLE). После унификации формата
7 HCM-тяжёлых агентов переобучены; v1-копии в `models/backup_v1/`.

## Шаг 5. Мастер-агент

Датасет 24k пар «случай + мнения специалистов → итоговый диагноз» из трёх
источников: DDXPlus 13.5k (мнения = топ гипотез дифдиагноза с вероятностями,
истина подмешивается с P=0.5, когда её нет в списке — конфликт мнений встроен
в данные), MedMCQA 8.1k (дистракторы вариантов = конфликтующие мнения,
объяснения = готовые рассуждения; покрывает все 14 классов), USMLE 2.4k.
Обучен med-chief-3b (train 0.556 / eval 0.355); шаг синтеза в конвейере 3–6 с.

## Шаг 6. Переводчики (сравнительный тест)

Тест на 175 парах RU↔EN (жалобы + медицинские термины + ответ мастера):

| Модель | Вход RU→EN | Выход EN→RU |
|---|---|---|
| MiLMMT-46-1B | лучший: «стул»→stool, «назначили»→prescribed, термины точны | непригоден: ломает заголовки, «groin»→«локоть» |
| NLLB-200-600M | хорошо, «стул»→chair | непригоден: «Reasoning»→«Разумство» |
| opus-mt (MarianMT) | хуже всех: «omeprasol», «The chair has grown» | непригоден |
| base Qwen2.5-3B | эталон, медленно | эталон: промпт сохраняет структуру и термины |

Принято: вход — MiLMMT резидентно (~1 с), фолбэки NLLB → Qwen; выход —
только Qwen. Всё локально.

## Шаг 7. Инференс-сервер

`inference/server.py` (FastAPI, порт 8010): `/api/case` (полный конвейер c
trace-таймингами), `/api/route`, `/api/agent`, `/api/translate`, `/api/health`.
Пост-обработка: канонизация дрейфа маркеров (Rationale/Answer → русские
заголовки), срез MCQ-букв, анти-CJK-чистка русских выдач.

Ключевое инженерное ограничение: сервер работает на чистом transformers —
`import unsloth` глобально патчит классы моделей, и при трёх и более
экземплярах повторные загрузки падают с illegal memory access, а смешивание
загрузок unsloth/transformers — с AttributeError (`apply_qkv`). unsloth
используется только в `train_model.py`.

## Шаг 8. Сквозной бенчмарк

175 RU-жалоб (улики DDXPlus, переведены в RU локально offline, seed 42;
золото классов — по расширенному маппингу), прогон через `/api/case`:

| Метрика | v1 | v2 |
|---|---|---|
| Маршрутизация | 30.9% | **79.4%** |
| по классам | — | Невролог 100, Онколог 96, Травматолог 96, ЛОР 84, Терапевт 80, Хирург 52, Гастро 48 |
| Латентность (медиана) | 37 с | 30 с; финальная конфигурация с MiLMMT ~21 с |
| CJK-утечки | 0 | 0 |

Финальная смока (5 случаев разных классов): маршрутизация 5/5, блок
«Итоговый диагноз» во всех ответах, латентность 17–30 с.

## Ошибки и решения

| Ошибка | Причина | Решение |
|---|---|---|
| Роутер «14.1%» на бенчмарке | золотой ответ попадал в промпт (`apply_chat_template` на полных messages) | промпт строится без assistant-реплики; сырые ответы сохраняются в отчёт |
| OOM обучения на длинных батчах (шаг 230/268) | batch 2×8 при max_len 2048: пик логитов ~1.2 ГБ + фрагментация | batch 1×accum 16 (проверенный рецепт), `expandable_segments` |
| MCQ «0%» у всех агентов | метрика знала только «Ответ:», модели дрейфуют на «Answer:» под инструкцией EN | регулярка принимает оба маркера; метрики пересчитаны офлайн по сохранённым ответам без GPU |
| Обрезка ответов посреди рассуждения | max_new_tokens=512 | 768–1024 |
| e2e v1: маршрутизация 30.9% | роутер обучен до расширения DDX-маппинга; новые классы ему не встречались | перегенерация датасета и переобучение (v2, 76.6%) |
| illegal memory access в сервере при смене агента | unsloth: повторные загрузки модели при 3+ живых экземплярах | весь инференс на чистом transformers |
| AttributeError `apply_qkv` | смешивание unsloth- и vanilla-загрузок: глобальный патч классов | исключён `import unsloth` из сервера |
| Краш после выгрузки переводчика | `empty_cache()` + повторная загрузка unsloth-модели ломает triton-ядра | выгрузка до загрузки; после отказа от unsloth — `empty_cache` безопасен и возвращён |
| OOM при 4 моделях | роутер+мастер+агент+переводчик = 24.8 ГБ > 23.5 | принудительная выгрузка переводчика после входа; агент выгружается до мастера |
| OOM очереди обучений | «тренировка-призрак» 21.5 ГБ: pkill не убил процесс | остановка по точному PID с верификацией; pkill-паттерны, не совпадающие с собственной командной строкой |
| CJK-иероглифы в русских ответах Qwen | особенность базовой модели | анти-CJK инструкция в промпте + `clean_russian_output` |
| MCQ-артефакт «D (Salt water)» в ответе | агент-экзаменационщик переносил букву варианта | срез префиксов «Ответ:/Answer: X.» в пост-обработке |
| Метрика «блок диагноза 0%» при валидных ответах | искала «Предварительный», а мастер выдаёт «Итоговый диагноз» | метрика принимает оба заголовка |
| Тихий прогресс бенчмарков | буферизация stdout при редиректе | фактический прогресс — по access-логу сервера |
| «Лог завис» в мониторе | застывший tqdm финальных баров | выбор самого свежего бара + возраст mtime |

## Запуск

```bash
.venv/bin/python -m inference.server --port 8010     # сервер
curl -s localhost:8010/api/case -H 'Content-Type: application/json' \
     -d '{"text": "Неделю болит горло, температура 38,5, налёт на миндалинах"}'
curl -s localhost:8010/api/health

.venv/bin/python scripts/download_en.py --all          # источники (идемпотентно)
.venv/bin/python scripts/prepare_specialties.py --per-specialty 100000 \
    --hcm-limit 20000 --uniform-format                 # наборы агентов
.venv/bin/python scripts/prepare_router.py             # роутер
.venv/bin/python scripts/prepare_chief.py              # мастер
.venv/bin/python scripts/train_model.py --data data/router            # или:
.venv/bin/python scripts/train_model.py --specialty Терапевт          # или:
.venv/bin/python scripts/train_model.py --data data/chief
.venv/bin/python scripts/benchmark_e2e.py --n 200      # e2e (RU-жалобы кэшированы)
```

## Ограничения

Маршрутизация Гастроэнтеролог 48% / Хирург 52% (взаимная путаница классов);
выходной перевод — только base Qwen; Проктолог — тонкий класс (1.1k примеров);
воспроизведение данных требует `data/raw/` (в git не входит, скачивается скриптом).
