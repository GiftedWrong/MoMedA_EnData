# Консилиум специалистов по марже роутера

Задача: система должна распознавать кейсы, где одного специалиста
недостаточно, и вызывать второго. Механизм — скоринг уверенности
генеративного роутера (без переобучения): при малой марже top-1/top-2
вызываются оба агента, мастер взвешивает два мнения (формат нескольких
пуль уже обучен в data/chief, шаг 5 README).

## 1. Калибровка (scripts/router_confidence.py)

Модель `med-router-en-v2-3b`, test-сплит 876 примеров. Скоринг: teacher
forcing 14 кандидатов «Рекомендуемый специалист: <Класс>.», средний
logprob/токен (нормировка длины обязательна — имена классов разной длины),
маржа ln(p1/p2).

- **Top-1 скоринга: 76.3%** — санити против 76.6% жадной генерации
  (ROUTER_BENCHMARK.md): скоринг отражает поведение модели.
- **Recall@2: 88.9%** — потолок механизма (+12.6 п.п. к top-1).
- Разделимость: медиана маржи у ошибочных маршрутов **0.06** против
  **0.20** у верных — сомнительные кейсы отличимы.

Порог (максимум покрытия при доле консилиумов ≤ 30%): **ln(p1/p2) = 0.08**
→ консилиум на 27% кейсов, покрытие 84.2% (+8.0 п.п. к top-1).

Кривая «порог → доля консилиумов → покрытие» и разбивка по классам:
`data/processed/ROUTER_CONFIDENCE.md`. Выгодные пары (золото на 2-м месте):
Травматолог+Хирург (8), Дерматолог+Стоматолог (7).

## 2. Реализация (inference/server.py)

- Шаг `route_score` (~0.7 с, резидентный роутер, под gpu_lock) возвращает
  (top-1, top-2, ln-маржу) до загрузки агентов.
- При марже ≤ `consult_margin` (config.yaml, по умолчанию 0.08; env
  `MOMEDA_CONSULT_MARGIN`, 0 = выключено) вызываются top-1 и top-2:
  два последовательных агентных прохода через LRU=1 (порядок выгрузок VRAM
  не меняется), затем мастер с двумя пулями мнений.
- `specialty` в ответе остаётся top-1 (совместимость); добавлены
  `specialties` и `consult`; скоринг-топ-1 страхует от 422.
- Пик VRAM 21.9 ГБ из 23.5 (транзиентные логиты скоринга ~2.3 ГБ,
  аллокатор переиспользует блоки) — в бюджете.

Смок (принудительный консилиум, margin=99): specialities
[Гастроэнтеролог, Терапевт], шаги agent:gastroenterologist 8.6 c +
agent:therapist 4.9 c (LRU-своп), chief взвесил оба мнения, латентность
34.9 с против ~26–29 с у одиночных кейсов.

## 3. Сквозной e2e (175 RU-жалоб DDXPlus, кэш)

Прогон с `consult_margin=0.08` (`runs/E2E_CONSULT_REPORT.md`; бейзлайн v2 —
`runs/E2E_REPORT.md`):

| Метрика | v2 (бейзлайн) | v2 + консилиум |
|---|---|---|
| Маршрутизация top-1 | 79.4% | 78.3% (разница — смена входного переводчика: бейзлайн-175 гонялся с Qwen-входом, этот прогон — на MiLMMT; top-1 генерация роутера консилиумом не менялась) |
| Recall@2 | — | **84.0%** (+5.7 п.п. к top-1 прогона) |
| Консилиумов | — | 27/175 (15%) |
| Латентность (медиана) | 30 с | 32 с · без консилиума 32 с · с консилиумом 59 с |
| CJK-утечки | 0 | 0 |

- Шаг `route_score` добавляет 0.7 с на кейс.
- Доля консилиумов 15% против 27% в калибровке: DDX-жалобы «легче»
  смешанного тест-сплита (top-1 выше), маржа чаще высокая.
- Главный выигрыш — Хирург: top-1 56% → recall@2 80% (+24 п.п., путаница с
  Травматологом ловится топ-2). Гастроэнтеролог почти не спасается
  (36% против 32%): его ошибки уходят глубже топ-2 (в основном в
  Дерматолога — см. выборку отчёта).
- Видимые проблемы качества ответов не связаны с консилиумом (диагностировано
  по-стадийно на сэмпле ЛОР: агент на анкете «да/нет»-вопросов уходит в
  режим ответов «Answer: No. No…» с пустыми блоками; мастер переносит мусор
  фолбэком «первые 200 символов»; переводчик выхода честно переводит).
  Мастер галлюцинирует и в бейзлайне («Грейвс'е болезнь» вместо миастении).
  Количественно разложит внешний судья MedGemma-27B (следующий этап,
  `runs/MEDGEMMA_JUDGE_REPORT.md`).

## 4. Дальнейшие шаги

- Решение мастера о дозапросе специалиста маркером «### Консультация» —
  влить в подготовку данных chief v2 (ReasonMed, тиры Differential
  Comparison); не конфликтирует с маржой роутера: маржа решает «кого
  позвать сразу», мастер — «кого дозапросить по ходу».
- Статический приор по парам путаницы (спасаемые: Травматолог↔Хирург,
  Дерматолог↔Стоматолог) как доп-триггер поверх маржи.
